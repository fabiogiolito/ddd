/ddd · a skill for AI agents

Edit the doc.
The code follows.

Doc-driven development keeps your app described in a folder of plain-language markdown docs. You read and change the docs; your agent keeps the code in line with them.

Download ddd.skill View on GitHub

Why docs, not code

Most people building with AI no longer read the code. They already write prompts and notes, but those get lost. ddd turns them into a structured, linked description of the whole app that anyone on the team can read and change.

01

Docs first

Every change, from a doc edit or a chat prompt, lands in docs/ before it lands in code.

02

Plan, then apply

The agent shows what changed and what it will do to the code, then waits for a yes. Nothing rebuilds silently.

03

Behavior, not implementation

Docs say what the app does, in words a product manager would use. Technical choices live in .tech/.

The loop

No server watches your files. At the start of every turn the agent checks what changed since the last build, so an edit you forgot to mention is never missed.

youEdit a docChange a rule, add a field, rename a page.
statusAgent noticesLists changed docs and the docs they affect.
planYou reviewWhat changes for users, conflicts, code touched.
applyCode followsDocs, code and tests updated, then marked built.

What it looks like

Each folder answers one question. Docs link to each other, and every feature ends with acceptance criteria that become tests.

docs/

docs/
├── app.md        # who uses it, glossary
├── data/         # what it remembers
├── features/     # what it does
├── pages/        # what people see
├── components/   # reusable pieces
├── integrations/ # auth, email, APIs
└── .tech/        # stack, for coders

  then it is blocked.

Commands

Invoke the skill with /ddd. The bundled script does the bookkeeping, with no dependencies beyond Python.

CommandWhat it does
/dddReports what changed in the docs since the last build
/ddd <request>Starts an app, applies a doc edit, or makes a change, docs first
docs_status.py statusChanged docs, what they affect, broken links
docs_status.py diff <doc>Line diff against the last built version
docs_status.py mark-appliedRecords the docs as built, after code and tests pass
docs_status.py restore <doc>Puts a doc back to its last built version

Install

Claude Code

Copy the ddd/ folder from the repo into ~/.claude/skills/, or into .claude/skills/ inside one project.

Other agents

Point your agent at ddd/SKILL.md. It is plain markdown.
